# Ticket Box Go

A small Go microservice project for identity and API gateway flows. The solution is split into:

- `services/identity-service`: gRPC identity service with MySQL persistence and domain logic
- `services/api-gateway`: HTTP gateway that exposes public endpoints and validates JWT tokens
- `gen`: generated protobuf code shared by the services
- `proto`: source `.proto` definitions

## Architecture

- `identity-service` owns user data and authentication logic.
- `api-gateway` is the public HTTP layer for browser/mobile clients.
- `mysql` stores the user table and is initialized through migration SQL files.
- JWT is used for API access tokens generated by the gateway and validated by the gateway middleware.

## Services

### Identity service

The identity service exposes gRPC methods such as:

- `CreateUser`
- `GetUserById`
- `GetUserByEmail`
- `AuthenticateUser`
- `UpdateUserProfile`
- `ActivateUser`
- `DeactivateUser`

### API gateway

The gateway exposes HTTP endpoints:

- `GET /health`
- `POST /register`
- `POST /login`
- `POST /logout`
- `GET /me`
- `GET /profile`
- `GET /users/me`

## Local development

Prerequisites:

- Go 1.26+
- Docker Desktop / Docker Engine
- Make sure the repo root is opened as the workspace root

Run the stack:

```bash
docker compose up --build
```

If you need to run Go tests locally:

```bash
go test ./services/identity-service/... ./services/api-gateway/...
```

## Environment variables

The API gateway expects:

- `PORT` (default: `8080`)
- `JWT_SECRET`
- `IDENTITY_SERVICE_ADDR`

The identity service expects:

- `APP_ENV`
- `APP_PORT`
- `MYSQL_HOST`
- `MYSQL_PORT`
- `MYSQL_DATABASE`
- `MYSQL_USER`
- `MYSQL_PASSWORD`
- `JWT_SECRET`

## Notes

The project is intentionally structured around a layered architecture:

- domain
- application
- infrastructure
- interfaces/grpc
- api-gateway

This keeps business rules and persistence concerns separate from HTTP and RPC adapters.
